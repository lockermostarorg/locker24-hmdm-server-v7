## Upstream gap: path parameters skip Guice filters

Guice-servlet matches `filter("/rest/xxx/*")` against the raw request URI, including `;` path parameters, while Tomcat and Jersey strip them before routing. So `/rest/private;x/...` skips `JWTFilter`, `AuthFilter` and `PrivateIPFilter`, and `/rest/internal;x/...` skips `InternalIPFilter`, while the resources are still reached. In this fork the only thing that blocks this for `/rest/private/*` is `SpaFilter.hasPathParameters` (`common/src/main/java/com/hmdm/rest/filter/SpaFilter.java`), which answers 400 to any URI containing `;` or `%3B`. That check is load-bearing: never remove `SpaFilter` from `web.xml` or reorder it after `guice-filter`. `/rest/internal/alert` additionally checks the caller in the resource itself (row above). Suggested upstream fix: reject path parameters in the Guice filter chain itself, or check authorization inside the resources, and send both this and the internal endpoint fixes back to Headwind.

Deviations of the health feature from the spec (sections 3.6, 3.7, 4.1) are listed in [`locker24-health.md`](locker24-health.md).
